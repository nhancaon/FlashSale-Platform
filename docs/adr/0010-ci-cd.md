# ADR 0010: CI/CD with GitHub Actions

## Status
Accepted (Phase 7)

## Context
Eight services in two languages, integration tests that need Oracle, Redis and Kafka, images to publish, and a
correctness claim (no oversell, no lost event) that only a running stack can check. CI must run the same commands as a
developer, so a red build can be reproduced locally.

## Decision
| Workflow | Trigger | What it does |
|---|---|---|
| `ci-go` | push/PR touching Go code | golangci-lint v2 per module (`services/.golangci.yml`); `make check-lua`; `go vet` + `go test -race` with coverage against the real Oracle/Redis/Kafka of `docker-compose.yml` |
| `ci-java` | push/PR touching Java code | `./mvnw verify` per service: tests (Testcontainers starts Oracle Free / Redis), Checkstyle (`services/checkstyle.xml`), JaCoCo report; coverage in the run summary |
| `docker` | push/PR touching services | build each image (Buildx, GHA cache), assert a non-root user, Trivy scan (fail on fixable CRITICAL), push `ghcr.io/<owner>/flashsale-<service>:<sha>` and `:latest` from main, Go vs Java size table in the summary |
| `security` | push, PR, weekly | Trivy on Go dependencies and on configuration (Dockerfiles, compose) |
| `ansible` | changes under `ansible/` | ansible-lint + `--syntax-check` + `--check`; skipped until the Phase 8 playbooks exist |
| `loadtest` | nightly, manual | whole stack per inventory implementation (go, java): `make e2e`, `make e2e-gateway`, then `loadtest/smoke.sh` (k6 thresholds + database reconcile) |
| Dependabot | weekly | gomod, maven, docker base images, actions; grouped per ecosystem |

- **Real infrastructure instead of mocks in CI.** Go integration tests use the compose stack (`make up` services), Java
  tests use Testcontainers. Both run the same migrations as production (`db/migrations`).
- **Lint checks mistakes, not taste.** golangci-lint's standard set plus gosec, errorlint, bodyclose, sqlclosecheck,
  rowserrcheck, noctx, misspell; Checkstyle with a short list of bug-prone patterns in the code's existing style (tabs,
  Spring conventions). Unchecked errors of deferred `Close` follow the `std-error-handling` preset. Every remaining
  `//nolint` states why (jitter with `math/rand`, `:1,:2` placeholders concatenated in an `IN` list).
- **Where each dependency is scanned.** Java dependencies are scanned in the image (the jar that actually ships, with
  transitive versions); scanning `pom.xml` needs the parent pom from Maven Central, which rate limits (429). Go modules
  are scanned from `go.mod`. A CVE accepted on purpose goes in `.trivyignore` with a reason.
- **Fail on fixable CRITICAL** in images (blocking), HIGH reported. Phase 7 fixed what the first scan found: Tomcat
  11.0.24 (3 CRITICAL) and Jackson 3.1.5 (HIGH) by pinning `tomcat.version` / `jackson-bom.version` ahead of the
  Spring Boot 4.1.1 BOM; `moby/go-archive` and `x/crypto` (HIGH) in ratelimiter-go by upgrading.

## Consequences
- `make lint`, `make security-scan` and `make loadtest-smoke` reproduce the CI checks locally.
- The image push uses the workflow's `GITHUB_TOKEN` (`packages: write`); no secret to manage. Packages appear under the
  repository owner on GHCR, private by default.
- The coverage of inventory-java looks low (about 39% lines) because its behaviour is exercised by the Go contract
  test suite over HTTP, which JaCoCo does not see; order (about 90%) and ratelimiter-java (about 89%) are tested in-process.
- Not done: deploy from CI (Phase 8 deploys with Ansible), signed images / SBOM attestation.
